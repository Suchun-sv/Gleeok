# Gleeok 代理会话与站点规则设计

日期：2026-11-04
状态：设计草案，待用户审阅；尚未实现。

## 目标与已确定的选择

用户希望在 Gleeok 中为网页选择普通会话或代理会话，并为 Gleeok 服务器、Paseo 连接分别选择网络方式。代理会话独立保存登录态，切换会话允许重新加载。配置为代理专用的链接在普通会话中必须被拒绝，只有从代理专用列表移除规则才能解除。用户已选择按站点域名匹配。

本设计面向 macOS 优先验证。实现放在 Gleeok 现有 Electron 网络与视图管理层，其他桌面平台复用相同的产品语义。

## 方案比较与选择

| 方案 | 特点与取舍 |
| --- | --- |
| 每个 tab 单独持久化 session | 每页都能设置代理，但同站点多个 tab 也会拥有不同登录态，管理成本较高 |
| 普通、代理两组共享 session | 各组内部共享登录态，组间隔离；切换需要重建网页视图，可能分别登录 |

用户接受独立代理 session 的方案，本设计采用第二种。所有项目与窗口共享这两组浏览会话；每个网页 tab 保存所属模式。

## 会话与网络方式

- 普通浏览会话沿用 `persist:gleeok`，保留已有登录态。
- 新增 `persist:gleeok-proxy`，供全部代理 tab 及其登录弹窗使用。
- 两组 Cookie、Local Storage、缓存、Service Worker 和权限记录分别管理。
- 代理会话持久化，重启保留登录态；提供“清除代理会话数据”。这是设计建议，供用户审阅。
- 普通浏览默认延续现有系统代理及本地/Tailscale 直连处理；网络设置可把整组普通网页改为显式直连。界面名称为“普通”，避免在自动代理开启时显示错误的“直连”状态。
- 代理浏览显式使用统一配置的本地代理地址，先完成 session 初始化再加载网页。该 session 不参与 `keepTailnetDirect()` 的系统代理定时刷新。
- 指定代理连接失败时显示错误并重试相同代理。代理模式没有 DIRECT 回退项，普通模式的本地/Tailscale 绕过规则也不带入代理模式。
- 显式处理 Chromium 默认的 loopback 绕过规则；使用固定代理时不能因目标是 localhost 就静默直连。回环地址、IPv4/IPv6 与代理端点本身须分别验证，防止代理循环。
- 首版配置一个代理入口，支持本地 HTTP（包括 HTTPS CONNECT）和 SOCKS5；无需认证的本地入口是首个验证场景。代理凭据支持可后续增加。

网络设置中的“测试代理”使用独立检测 session，显示连通性和检测时间。常规网页加载不强制进行出口 IP 或地区校验。

代理模式的网页 HTTP、HTTPS、WS、WSS 连接属于首版代理路由的验收范围。WebRTC 另行处理：代理网页与弹窗在首次加载前设置 `disable_non_proxied_udp`，禁止非代理 UDP；指定代理无法承载的实时通信允许失败，不自动放开直连，也不为此改回普通模式。摄像头/麦克风权限不能代替 WebRTC 数据通道的网络检查。实现时用受控 STUN/TURN 与网络日志验证该策略在目标 Electron/macOS 版本上的实际行为；若仍出现非代理通信，必须修正或限制相关能力后才能把它列为已覆盖。首版不承诺实时通话的可用性。这一取舍是设计建议。

## 站点域名规则

设置 → 网络 → 代理专用站点，保存一份本机共享的域名列表。项目中的 Link 根据 URL 匹配该列表并显示代理标记。规则跨项目、栏和窗口生效，不依赖某个收藏记录是否还存在。

域名规则采用明确的 hostname 及其子域：

- `chatgpt.com` 匹配自身与 `*.chatgpt.com`，包括全部路径、查询参数、端口，以及 HTTP、HTTPS、WS、WSS 请求。
- `chatgpt.com.example.org`、`otherchatgpt.com` 不匹配 `chatgpt.com`。
- 若录入 `app.paseo.sh`，匹配范围是该主机及其子域；不自动扩大为整个 `paseo.sh`。
- 通过 URL 解析及 IDNA 规范化处理大小写、国际化域名和末尾的点；按完整域名标签边界匹配。
- 规则编辑界面显示最终匹配的域名。规则授权判断不复用当前用于密码库的近似 `baseDomain()`。
- 域名列表首版针对 DNS 主机名；本地代理地址属于连接配置，与此列表分别校验。

“标记为代理专用”是一项持久操作。“在代理会话中打开”只是选择打开位置，不会把浏览过程中遇到的每个站点自动加入列表。

关闭代理 tab、退出应用、取消收藏、修改代理地址、代理不可用，都不移除站点规则。解除限制的入口统一为代理专用列表中的“移除规则”。

## 打开与拦截行为

| 场景 | 行为 |
| --- | --- |
| 普通会话打开未标记站点 | 正常打开 |
| 普通会话打开代理专用站点 | 请求发出前拦截，显示原因 |
| 代理会话打开代理专用站点 | 通过指定代理打开 |
| 代理会话打开其他站点 | 继续使用代理会话及指定代理，支持登录跳转等流程 |
| 把代理专用站点的 tab 切到普通模式 | 拒绝切换，保留代理模式 |
| 从列表移除规则 | 允许以后在普通模式打开；现有代理 tab 保持当前模式 |

普通会话的拦截提示显示目标域名，提供“在代理会话打开”和“管理代理专用站点”。不提供单次绕过。用户明确选择代理打开时，原有普通 tab 保持原模式，新建或激活代理 tab。

所有入口使用同一判断：地址栏、项目 Link、新标签页、右键跨栏打开、网页链接、新窗口、OAuth 弹窗、前进后退、HTTP 跳转、关闭后恢复、休眠唤醒、崩溃恢复和远端标签页接力。

从网页产生的新 tab、跨栏新 tab 和登录弹窗继承来源模式。通过显式“在代理会话打开”创建的 tab 使用代理模式。内置日程、文献库和终端 UI 使用现有内部页面处理，不提供浏览会话切换。

## 统一请求防线与运行中的规则变更

主进程的显式打开入口负责及时给出提示；普通浏览 session 的请求拦截器负责在网络请求层检查目标域名。因此 iframe、图片、脚本、fetch/XHR、WebSocket 握手、Worker/Service Worker 和下载请求也适用规则，不能依赖 tab URL 或 `webContentsId` 存在才执行检查。

导航事件用于控制界面反馈和弹窗，session 请求判断作为统一兜底。应覆盖应用代码直接调用 `loadURL()` 的路径，因为它们不一定触发可取消的用户导航事件。

新增规则时按以下顺序处理：

1. 保存规则并更新主进程内的规则快照，让新请求立即使用新规则；保存失败则不报告成功。
2. 找出普通会话中已打开的匹配页面，停止并销毁相关网页视图，显示拦截提示；不自动迁移登录态或重新打开目标页面。
3. 取消相关进行中下载，终止普通会话的现有连接，防止旧 WebSocket 等继续工作。共享 session 的连接重置可能让其他普通网页短暂重连，应在操作提示中说明。
4. 清理匹配站点的 Service Worker 注册及相关缓存，确保后续恢复不继续执行旧页面。规则存在时，后退与恢复同样显示拦截状态。

缓存或 Service Worker 命中的受保护顶层页面也不能在普通模式显示。实现时需用带 Service Worker 的测试站点验证实际 Electron 版本的行为；若清理不能停止既有后台执行，必须采用受控重启相关浏览环境的路径后才报告该规则完成应用。

规则文件损坏或无法加载时，应暂停网页恢复并显示配置错误，保留原文件供修复；不能当成空列表继续恢复浏览。

## tab 状态与切换

Tab 增加可选的 `browsingMode: 'normal' | 'proxy'`，旧状态缺省为普通。关闭恢复记录也保留模式。

切换模式时销毁原 WebContentsView，再用目标 session 创建视图并重新加载。切换不复制 Cookie、Local Storage、页面表单、历史栈或其他运行状态。界面在执行前说明未保存的页面内容会丢失。代理专用域名不能切回普通模式。

重启前保存的代理 tab 仍按代理恢复。代理配置缺失或初始化失败时显示代理配置提示，保留 tab 模式与站点规则。

代理会话的 Cookie 等数据可以被清除，站点规则单独保存；清除会话数据不会解除站点限制。

## 设置与本机存储

设置 → 网络包含：

- 代理协议、监听地址、端口，以及测试结果。
- 普通网页连接：自动（默认）或直连。
- 代理专用站点列表，支持新增、查看匹配范围、移除。
- 代理会话数据清理。

tab 的地址栏/右键菜单提供普通与代理模式选择。项目 Link 旁的代理标记根据本机域名列表计算。阻止打开时保留用户输入，不产生目标站点请求。

代理地址、域名规则、普通网页连接设置、服务器和各 Paseo 连接选择均保存在本机。tab 的浏览模式随本机 state 保存。现有跨设备标签页 URL 同步保留；接收设备按自己的域名规则重新检查，不能继承另一台设备的本地端口或绕过本机规则。当前 DeviceSession 不携带模式，远端接力的 tab 按本机普通模式接收，匹配代理专用域名时停在拦截提示，再由用户选择代理打开。

配置写入使用原子替换；运行时规则版本与异步连接重建绑定，过期任务不能覆盖更新后的模式。

## Gleeok 服务器连接

设置 → 同步增加独立的直连/代理选择及连接测试。本地模式显示“本地”，没有外部服务器网络设置。

此选择统一覆盖 ConfigClient 的请求，包括项目与标签页同步、日程、文献库和附件传输。通过服务专用 transport/session 发出，保留 Bearer 认证、超时、离线缓存与冲突处理；不使用网页 Cookie jar。

旧安装缺省设置保留当前后台连接路径，直到用户首次选择明确的直连或代理。选择后 UI 显示已应用的模式。切换终止旧 transport 的请求，之后的请求使用新模式；不自动重放结果未知的写入请求。失败显示离线与具体原因，缓存继续可用。

网页站点限制属于浏览规则。服务器连接使用本节的显式配置，不因同一域名在网页列表中出现而静默改变 transport。

## Paseo 连接

设置 → Paseo 的每台设备增加独立直连/代理选择、连接测试和错误状态。本机 `127.0.0.1:6767` 默认直连。旧配对缺省保持现有连接路径，用户明确选择后保存本机设置。

后台目录同步的 HTTP 和 WebSocket 都使用设备的选择。服务专用 transport 与网页 session 分开；不能仅修改 Electron 网页代理，也不能通过进程级环境变量切换整台应用的网络。

Paseo SDK 继续承担协议与 E2EE。实现计划需要先核对已锁定 SDK 版本的 WebSocket 注入能力：优先使用 SDK 支持的 transport/factory 扩展；若没有，选择最小的、版本明确的适配补丁，并验证 HTTP/SOCKS5 与 E2EE 均能工作。不能把后台仍然直连的状态显示为“代理”。

从该设备打开的 Paseo 托管网页 Link 默认采用设备选择；随后 tab 选择只影响网页，不修改后台同步。域名限制优先于设备默认值：设备选择直连但其网页域名被标为代理专用时，普通网页打开被拒绝，并展示代理打开入口。

Paseo 网页在代理会话中需要独立完成浏览器配对。新增配对时应在对应浏览模式中完成网页配对，而不是依赖普通 session 的 Local Storage。

配对与目录读取、目录写入 Gleeok 服务器是两段独立连接，分别使用 Paseo 与 Gleeok 服务器的设置。选择代理不会改变远端 daemon 上运行的 agent、命令或 SSH 的网络方式。

## 实现边界与代码落点

本功能管理 Gleeok 内的浏览请求和指定后台连接。系统 VPN/TUN 仍可能接管操作系统流量；网页的“代理”标记表示应用已应用指定配置，不表示验证了公网出口身份。

主要代码落点：

- 新增网络设置/域名策略模块：URL 规范化、模式解析、本机持久化和服务 transport。
- `shared/src/model.ts` 与 `shared/src/ipc.ts`：tab 模式、网络状态与动作。
- `app/src/main/views.ts`：按模式创建 view、弹窗与模式继承。
- `app/src/main/index.ts`、`state.ts`、`contextmenu.ts`：统一打开检查、恢复和模式切换。
- `app/src/main/proxy.ts`：普通会话现有规则、代理会话固定设置、初始化与更新顺序。
- `permissions.ts`、`downloads.ts`、`compat.ts`：注册到相应 session；下载汇总显示、权限记忆分别保存。
- `config.ts` 与 `paseo.ts`：后台 HTTP/WebSocket transport。
- renderer 的设置、Paseo 设置、标签工具栏与 Link 操作。

每个 session 的 `webRequest` 同一事件只保留一个监听器；域名检查和现有登录兼容逻辑须统一编排，不能通过后注册覆盖已有处理器。网页 session 初始化必须在任一 view、弹窗或恢复请求产生前完成。

## 验收标准

以受控站点与带计数日志的本地代理验证网络实际行为，而不只检查 UI 状态。

1. 同站点普通/代理登录态隔离，同组多个 tab 共享登录态；重启保留代理登录态。
2. 普通会话访问代理专用域名被拒绝，测试站点未收到请求；代理会话请求出现在指定代理日志。
3. 子域、全部路径、参数、HTTP/HTTPS 与 WS/WSS 匹配；相似后缀域名不误拦；IDNA、大小写和末尾点规范化可验证。
4. 地址栏、收藏、右键跨栏、新窗口、跳转、前进后退、关闭恢复、崩溃恢复和远端接力都遵守同一规则。
5. 普通页面的 iframe、fetch、Worker、Service Worker、WebSocket 与下载访问受保护目标时也被阻止；新增规则能停止已有受保护页面与长连接。
6. 只有移除域名规则才能解除限制；关 tab、清 Cookie、代理故障或改地址均保留限制。
7. 代理停止、配置缺失或初始化失败时，代理 tab 保持代理模式并报错，不能改用普通会话加载。
   WebRTC 测试还应确认非代理 UDP 被禁止；代理不支持实时通信时不通过直连恢复功能。
8. Gleeok 服务器的项目/日程/文献库/附件请求遵守服务选择，读写语义与离线缓存继续有效。
9. Paseo 的状态读取、配对 relay WebSocket 和 E2EE 目录读取遵守所选连接方式；浏览器配对与后台连接各自验证。
10. 更换代理入口、快速切换模式、重启恢复和配置损坏场景不会使用过期 transport 或丢失域名限制。

具体模块拆分和测试工具由实现计划决定。构建及实际网络验证的运行机器在开始执行前由用户指定；设计阶段只进行源码阅读与文档检查。

## 审阅时需要注意的设计建议

以下是本设计提出的默认值，而非用户已逐项确认的选择：代理会话持久化；域名规则包含子域；站点规则保存在本机；普通会话保留已有自动网络方式，并可全局改为直连；标记当前已打开站点时可能重置普通会话的共享连接；首版使用一个无认证本地代理入口；代理模式限制非代理 WebRTC UDP，并接受不兼容的实时通信功能失败。用户已明确确认两组会话、普通模式拒绝代理专用链接、移除规则才能解除及按站点域名匹配。
